# 진격의 거인 Android 도트 생존 게임: 1탄 확정 설계

작성일: 2026-10-10 UTC  
상태: 2026-10-10 제품 설계. 주둔병사 시점·30분 생존 뒤 대피/탈출 조건·Godot 접근을 채택한다. 최종 아트와 Android 실기기 검증은 미완료다.

## 1. 목표와 확정 요구

사용자가 설치해 첫 판부터 완주를 시도할 수 있는 Android 2D 도트 뱀서라이크 게임을 만든다.

- 배경은 진격의 거인이며, 1탄은 원작 시간순에 맞춰 제작한다. 향후 최종 엔딩까지 확장할 수 있도록 챕터를 분리한다.
- 캐릭터 에셋이 완성될 때마다 원본 도트와 실제 게임 표시 크기, 준비된 이동·공격 애니메이션을 중간에 보여준다.
- Android 앱이며 가로·세로 화면을 모두 지원한다.
- 생존 타이머 기준 5·10·15·20·25분에 중간보스, 30분에 최종보스가 등장한다.
- Xbox 버튼 표기를 따르는 표준 Android 게임패드를 지원한다.
- 캐릭터, 일반 적, 보스, 배경, UI 그림, 효과, 사운드 자산을 직접 만든다. 기존 게임 자산을 추출하거나 재사용하지 않고, 조잡한 SVG나 임시 도형을 최종 자산으로 삼지 않는다.
- GitHub 사용자 shaterguy의 새 비공개 저장소에 소스를 보존한다. 저장소명은 별도 생성 단계에서 확정한다.
- Work 모드, cloud task, GitHub Actions를 사용하지 않는다.
- 본격 제작 전에 유명 동종 게임의 영상과 자료를 조사한다. 조사 결과는 별도 비교조사 문서에 있다.
- 작업은 공통 규격을 정한 뒤 독립 영역을 적극 병렬화하고 통합 검증한다.

## 2. 제품 결정

아래는 요구사항을 구체화한 제품·기술 결정이다.

1. 1탄은 845년 시간시나구 함락을 배경으로, 당시 주둔병사 한 명의 시점에서 주민 대피를 돕는 이야기로 확정한다. 플레이어는 사용자가 지정하지 않은 가상의 병사이며, 당시 어린 에렌을 숙련된 전투병으로 만들지 않는다.
2. 생존구간은 30분이다. 30:00에 갑옷 거인이 최종 위협으로 등장하고 생존 타이머가 멈춘다. 최종 구간은 대피 완료 후 탈출 지점에 도착하면 클리어한다. 원작 초반에 맞춰 갑옷 거인을 처치하는 결말은 쓰지 않는다. 현실의 한 판 길이는 일시정지·성장 선택·마지막 퇴각 때문에 30분을 넘을 수 있다. 이는 기존 '최종보스 처치 클리어' 가정을 스토리 요구에 맞춰 대체한 결정이다.
3. 싱글플레이·오프라인이며 계정, 광고, 결제, 서버, 클라우드 저장을 넣지 않는다.
4. 회전·일시정지·앱 전환 때문에 한 판이 초기화되지 않는다. Android 프로세스가 종료되면 최근 안전 체크포인트에서 재개한다.
5. 자동공격·자동 목표 선택이 기본이다. 이동과 회피를 조작하고 입체기동 공격은 게임 방식에 맞게 자동 실행한다. 수동 조준은 첫 APK의 필수 기능으로 넣지 않는다.
6. 첫 APK는 자체 제작한 병사 1명, 시간시나 시가지 스테이지 1개, 공격/지원 성장 6계열, 패시브 8종, 일반 거인 행동 5종, 중간보스 패턴 5종, 최종 위협 1종을 갖춘 완주 가능한 1탄을 목표로 한다. 후속 챕터의 실제 콘텐츠는 지금 만들지 않는다.

주둔병사 시점과 '30분 + 마지막 퇴각' 클리어 조건을 채택했다. 마지막 대피 진행은 초기 75초로 설정하며, 대피 완료 뒤 탈출 영역에 도착해야 승리한다. 60~90초 범위의 밸런스 조정은 가능하나 최종보스 등장 시점 30:00은 고정이다.

[공식 1화 시놉시스](https://shingeki.tv/season1/story/episode_01.php), [공식 2화 시놉시스](https://shingeki.tv/season1/story/episode_02.php), [공식 인물 연표](https://shingeki.tv/season1/character/), [MBS 2화 소개](https://www.mbs.jp/shingeki/sp/select-1st/02.shtml)를 확인했다. 함락은 845년이며 에렌의 훈련병 입단은 847년, 전투 참여는 850년이다. 주민의 탈출을 위해 주둔병단이 시간을 번다는 시점이 초기 사건에 맞는다.

오프닝은 초대형 거인의 출현과 성벽 붕괴, 플레이는 거인 침입과 대피로 확보, 마지막은 갑옷 거인의 위협과 퇴각으로 구성한다. 30분 시간표와 5개 중간보스는 게임용 각색이며 원작의 실제 분 단위 사건이라고 설명하지 않는다. 초기 장비는 쌍검·입체기동·성벽 고정포에 한정하고 뇌창·후반 거인 능력·후반 인물 정체를 섞지 않는다. 원작 대사·애니 프레임·음악은 복제하지 않고 짧은 상황 설명과 이벤트 문구를 직접 작성한다.

## 3. 구현 접근 비교와 권장안

| 접근 | 장점 | 부담·위험 | 판단 |

| Unity 2D | 편집 도구와 기존 게임 제작 생태계가 크다. | 현재 설치·라이선스·Android 도구 상태가 확인되지 않았다. 이번 규모에서 추가 설정과 의존성이 늘어날 수 있다. | 현재는 채택하지 않는다. |

이는 개발 효율에 관한 설계 판단이며 세 엔진의 성능 벤치마크 결과가 아니다. 현재 환경에서 Godot 4.6.3 실행 성공을 확인했다. Java·Node·Python은 있으나 Android SDK·export templates·javac·gradle·adb는 조사한 경로에서 확인되지 않았다. 설치나 빌드는 아직 실행하지 않았다. 환경 문제를 이유로 게임 디자인을 축소하지 않으며, 승인 뒤 패키징 가능성을 먼저 확인한다.

기술 근거: [Godot Android 내보내기](https://docs.godotengine.org/en/4.6/tutorials/export/exporting_for_android.html), [뷰포트·해상도 처리](https://docs.godotengine.org/en/4.6/tutorials/rendering/multiple_resolutions.html).

## 4. 핵심 플레이

### 4.1 한 판의 흐름

시작 화면 → 1탄 도입 → 시가지 진입 → 이동·회피와 자동공격 → 경험치·보급 수집 → 레벨업 시 전투 정지 및 3지선다 → 중간보스 격파와 대피로 확보 → 30분 최종 위협 → 마지막 주민 대피·퇴각 → 클리어 또는 사망 결과 → 다시 시작.

- 시작 20~30초 안에 첫 성장 선택을 경험하게 하는 것을 밸런스 목표로 둔다.
- 공격/지원은 한 번에 최대 4계열을 사용하며 각 계열을 강화하거나 다른 계열을 고른다.
- 6계열은 쌍검 전방 베기, 회전 베기, 입체기동 돌진 베기, 재진입 연속 베기, 성벽 고정포 지원, 동료 엄호로 정한다. 같은 초기 장비의 공격 방식·지원 차이이며, 원작에 독립된 여섯 무기가 있다고 주장하지 않는다. 거인의 목덜미 약점을 2D에서 읽기 쉬운 위치·표식과 공격 연출로 표현한다.
- 패시브는 피해량, 발사 간격, 이동, 체력, 회복, 수집 범위, 공격 범위, 방어의 8축을 사용한다.
- 최대치 아이템은 더 이상 무의미한 선택지로 나오지 않는다. 유효한 새 선택지가 부족하면 회복을 포함한 명확한 대체 보상으로 처리한다.
- 보스 보상은 회복과 확정 성장 선택을 함께 제공한다. 보상 오버레이 중에는 적과 타이머가 멈춘다.
- 첫 버전은 설정·최고 기록·1탄 클리어 기록·최근 런 재개를 저장하며 영구 능력치 구매는 넣지 않는다. 첫 판의 밸런스를 영구 강화에 의존시키지 않기 위해서다.

### 4.2 30분 구성

| 구간·시점 | 전투 목적 | 중간보스의 구분되는 패턴 |
|---|---|---|
| 0~5분 / 5:00 | 성벽 붕괴 직후 골목의 대피로를 연다. | 돌진 기행종: 방향 예고 후 직선 돌진한다. 옆으로 피하는 습관을 만든다. |
| 5~10분 / 10:00 | 느린 거인과 빠른 거인을 섞는다. | 팔 휘두르기형: 넓은 부채꼴 위험을 예고한다. 빈 통로를 고르게 한다. |
| 10~15분 / 15:00 | 광장을 지나 주민 이동을 돕는다. | 도약형: 바닥 표식 후 착지 공격한다. 움직임을 유지하게 한다. |
| 15~20분 / 20:00 | 좁은 거리와 거인 무리가 겹친다. | 잡기형: 길게 뻗는 팔과 접근 경로를 구분한다. 초능력 소환을 쓰지 않는다. |
| 20~25분 / 25:00 | 완성한 공격 조합으로 퇴각로를 확보한다. | 복합 기행종: 돌진과 휘두르기를 순차 사용한다. |
| 25~30분 / 30:00 | 마지막 주민을 선착장 방향으로 유도한다. | 갑옷 거인: 30:00 최종 위협으로 출현한다. 공격으로 처치하지 않고 돌진·잔해를 피해 대피를 완수한다. |

일반 적은 느린 추격·빠른 접근·큰 체구·팔 휘두르기·잡기 행동을 갖춘 거인으로 구분한다. 5개 중간보스는 게임용 강적 변형으로, 후반부 네임드 거인들을 초반에 배치하지 않는다. 뒤 구간은 단순 체력 증가 외에 구성·밀도·속도를 변화시킨다. 수치는 데이터로 분리하여 플레이 결과에 따라 조정한다.

보스 예약은 타이머가 임계값을 통과했을 때 1회 발생한다. 프레임 드롭, 일시정지, 저장 복원, 회전으로 중복되거나 누락되지 않는다. 중간보스가 남아 있어도 다음 예정 보스는 제시간에 등장하며, 뒤 보스를 지연시키는 숨은 조건을 두지 않는다. 처치 보상은 보스 ID별 1회다.

30:00에는 일반 거인의 신규 생성이 멈추고 최종 퇴각 이벤트가 열린다. 전환 예고 뒤 이전 구역의 적은 보상 없이 정리하되 플레이어 체력·성장·장비는 유지한다. 갑옷 거인의 체력바 대신 '대피 완료' 목표와 탈출 경로를 표시한다. 60~90초의 마지막 회피 구간을 초기 밸런스 목표로 삼고, 대피 완료 뒤 탈출 구역에 도달해야 클리어한다. 탈출과 플레이어 사망이 같은 시뮬레이션 틱에 발생하면 사망을 우선해 이중 결과를 방지한다.

## 5. 화면과 입력

### 5.1 화면 구성

- 시작: 게임명, 계속하기가 있으면 계속하기, 새 게임, 설정. 한 화면에 큰 선택지만 둔다.
- 전투 HUD: 최상단 경험치, 체력·시간·레벨, 현재 대피 목표, 중간보스 체력과 이름, 일시정지 버튼. 최종 구간은 대피 진행·탈출 방향을 크게 표시한다. 장비 상세는 일시정지 화면으로 옮긴다.
- 성장: 큰 아이콘, 이름, 현재 단계와 다음 단계, 실제 변화량을 보여주는 3개 카드. 전투가 정지하고 배경은 약하게 어두워진다.
- 일시정지: 계속, 설정, 이번 판 종료. 종료 선택은 별도 확인하여 오조작을 막는다.
- 결과: 승리·사망, 생존 시간, 보스전 시간, 처치 수, 최종 장비, 다시 시작·메뉴.

세로 화면에서는 성장 카드 3개를 세로로, 가로에서는 가로로 놓는다. 버튼 최소 터치 영역은 48dp 상당을 목표로 하며 컷아웃·상태바·제스처 영역을 피한다. 360×800, 800×360, 800×1280, 1280×800 화면을 기본 검증 크기로 삼는다. 실제 Android 화면 밀도에서 다시 확인한다.

### 5.2 가로·세로 회전

- 전투 상태는 화면 노드와 분리한 RunState가 소유한다. 회전 때문에 적·보스·드롭·쿨다운·난수 상태·시간이 재생성되지 않는다.
- 게임 월드의 단위와 속도는 일정하다. 짧은 화면 축을 기준으로 카메라 가시 범위를 잡고 긴 축에 더 많은 월드를 보여준다. 비율을 무리하게 늘리거나 캐릭터를 찌그러뜨리지 않는다.
- 가시 범위 변경이 적 생성의 난수 순서나 보스 공격 주기를 바꾸지 않는다. 방향별 시야 차이는 PvE의 허용된 차이이며, 화면 밖에서 피할 수 없는 즉발 공격을 만들지 않는다.
- 회전 시 입력을 해제하고 레이아웃이 안정될 때까지 시뮬레이션을 잠깐 정지한다. 성장 카드가 열려 있으면 같은 선택지·같은 의미의 포커스를 보존한다.
- 앱이 백그라운드로 가면 자동으로 일시정지한다. 복귀 시 자동으로 전투를 재개하지 않는다.

### 5.3 터치와 Xbox 기준 Android 게임패드

| 동작 | 터치 | Xbox 기준 패드 |
|---|---|---|
| 이동 | 화면 하단 이동 영역의 가상 스틱 | 왼쪽 스틱 또는 D-pad |
| 메뉴 탐색·성장 선택 | 항목 터치 | D-pad 또는 왼쪽 스틱 |
| 확인 | 버튼 터치 | A |
| 뒤로·취소 | 뒤로 버튼 | B |
| 일시정지·계속 화면 | 일시정지 버튼 | Menu/Start |

- 모든 시작·설정·성장·결과 화면을 패드만으로 조작할 수 있다. 처음 열릴 때 유효한 항목에 포커스가 있으며 모달 밖으로 포커스가 빠지지 않는다.
- 이동 입력은 공통 action으로 합친다. 원형 deadzone의 초기값은 0.20이며 설정에서 0.10~0.35로 조절한다. 작은 스틱 잡음으로 입력 방식이 바뀌거나 캐릭터가 움직이지 않아야 한다.
- 메뉴 스틱 탐색은 이동과 분리한다. 처음 즉시 반응한 뒤 300ms 대기, 이후 100ms 간격으로 반복하며 중립 복귀에 히스테리시스를 둔다. 값을 수동 테스트에서 조정할 수 있다.
- 실제 유효 입력을 기준으로 터치/패드 안내를 전환한다. 연결 사실만으로 터치를 막지 않는다. UI 안내의 A/B 아이콘은 자체 제작한다.
- 사용 중인 패드가 끊기면 이동값을 0으로 만들고 즉시 일시정지한다. 재연결하거나 터치로 바꾼 뒤 사용자가 명시적으로 계속한다. 연결 직후 눌린 A를 자동 확인으로 처리하지 않는다.
- 앱이 비활성 상태면 패드 입력을 무시한다. 활성 전투에서는 화면 꺼짐을 방지하고 백그라운드에서 계속 실행하지 않는다.
- 첫 버전은 단일 플레이어·활성 패드 1개다. 표준 Android 입력을 지원한다는 목표와 특정 Xbox 모델·Bluetooth/USB 조합에서 시험했다는 주장을 구분한다.

공식 근거: [Godot 4.6 패드 입력](https://docs.godotengine.org/en/4.6/tutorials/inputs/controllers_gamepads_joysticks.html), [Android 표준 컨트롤러 입력](https://developer.android.com/games/sdk/game-controller/controller-input). Android는 데스크톱과 입력 구현이 다르며 D-pad 반복·포커스·화면 꺼짐을 각각 검증해야 한다.

## 6. 자체 제작 아트·오디오

아트 방향은 진격의 거인 1탄의 성벽·붉은 지붕 시가지·벽돌 골목·주둔병사·거인·입체기동을 새로 그린 도트 팬게임으로 만든다. 사용자 개인용 비공개 개발이며, 원작 IP를 공식 제작물로 오인시키지 않는다. 원작을 알아볼 수 있는 설정은 살리되 애니 장면·기존 게임 스프라이트·공식 로고·음원을 추출하지 않는다. 인물 목록은 아직 사용자가 지정하지 않았으며 첫 플레이어는 주둔병사 1명으로 정했다.

- 고정된 약 24색 핵심 팔레트를 먼저 정한다. 벽돌·지붕은 낮은 채도의 적갈·회색, 병사 의상은 갈색·백색·짙은 녹색, 위험 표식은 주황·적색으로 구분한다. 거인의 피부색이 배경과 섞이지 않도록 명도·외곽선을 관리한다. 형태도 함께 사용해 색만으로 의미를 전달하지 않는다.
- 기본 배경 타일 32×32, 병사 셀 32×32, 일반 거인 48×64 또는 64×96, 강적 96×128 이상, UI 아이콘 24×24 또는 32×32의 래스터 기준을 사용한다. 거인이 병사와 같은 키로 보이지 않도록 크기 대비를 유지한다. 초대형 거인은 도입부 전용 큰 배경 스프라이트로 다룬다.
- 병사·거인은 대기·이동·피격·사망, 중간보스는 예고·공격을 추가한다. 갑옷 거인은 공격·진입·퇴각 이벤트에 필요한 프레임만 만들며 처치 애니메이션은 넣지 않는다. 이동 4~6프레임, 공격은 읽을 수 있는 예고와 타격 프레임을 분리한다.
- 이미지 생성 도구를 쓰더라도 한 장의 스타일 기준을 공유하고 실루엣·조명·색·프레임 정렬을 검수한다. 흐린 생성 이미지를 단순히 축소해 도트라고 부르지 않는다. 최종 시트는 배경 투명도·셀 경계·발 위치·픽셀 크기를 확인한다.
- UI 테두리·버튼·아이콘·포커스·보스 경고도 직접 만든 PNG/애니메이션을 쓴다. 텍스트는 읽기 쉬운 적법한 시스템/오픈 폰트로 표시하며 폰트 라이선스는 따로 확인한다.
- 효과음은 자체 합성·제작한 발사, 타격, 피격, 경험치, 레벨업, 보스 등장, 선택/취소, 승리/사망을 준비한다. 배경 음악은 자체 제작한 반복 가능한 짧은 전투 루프와 보스 변주를 사용한다. 최종적으로 제3자 게임 음악을 넣지 않는다.
- 자산 목록에 파일·용도·원본 제작 방법·치수·프레임 수·권리/출처를 기록한다. 참고 조사 캡처는 게임 파일에 넣지 않는다.
- 플레이어 외곽선, 거인 공격의 예고, 낙하 잔해는 아군 화려한 효과 위에서도 구분한다. 숫자·화면 흔들림·효과 강도를 낮출 수 있다.
- 캐릭터 에셋 하나가 준비되면 전체 게임을 기다리지 않고 원본 해상도 PNG와 실제 게임 배율 미리보기를 사용자에게 전달한다. 이동/공격 시트가 준비되면 짧은 애니메이션 미리보기를 추가한다. 시트의 빈 칸·프레임 불일치·배경 잔여를 먼저 확인하고, 미완성 시안과 최종 적용 자산을 구별한다.

## 7. 구조와 상태 보존

구성은 RunState/시뮬레이션, Combat/성장, SpawnDirector/Boss, Presentation/UI, InputRouter, Persistence, Android 패키징으로 나눈다. 각 부분은 공통 데이터와 명시적인 이벤트로 연결한다.

- 시뮬레이션 시간은 실제 전투가 진행되는 고정 스텝으로 센다. 시스템 시계 변경, 메뉴 대기, 프레임 수에 의존하지 않는다.
- RunState에는 seed와 난수 상태, 경과 틱, 플레이어, 무기·강화, 적·드롭·보스 상태, 이미 발생한 보스 ID, 보상 지급 ID, 현재 모달과 선택지가 들어간다.
- 회전은 동일 RunState의 표현만 바꾼다. 프로세스 종료 복구는 버전이 있는 로컬 체크포인트를 사용한다.
- 체크포인트는 30초 간격, 성장 선택 완료, 보스 출현·처치, 일시정지·앱 전환에 저장한다. 임시 파일에 쓰고 검증 후 교체하여 손상된 파일이 정상 저장을 덮지 않도록 한다.
- 저장 실패는 조용히 성공으로 처리하지 않고 일시정지 화면에 알려준다. 호환되지 않는 저장은 기존 파일을 보존하고 새 게임/재개 불가를 명확히 표시한다.
- 최대 적·투사체 수, 경험치 드롭 병합, 화면 밖 업데이트 빈도, 충돌의 공간 분할을 사용해 30분 누적 부하를 관리한다. 정확한 상한은 성능 측정으로 결정하며 적을 줄여 시간표 자체를 생략하지 않는다.
- 인터넷·계정 권한을 요청하지 않는다. 저장은 앱 전용 공간에 한정한다.

### 최종 엔딩까지 이어질 확장 경계

공통 전투·입력·UI·저장 엔진과 챕터 콘텐츠를 분리한다. 챕터 데이터는 안정된 chapter_id, 원작 시점, 지도·시작 위치, 사용 가능한 인물/장비, 적·보스 시간표, 스토리 이벤트, 클리어 조건, 다음 챕터 해금 조건을 갖는다. 이번에는 chapter_01_shiganshina 하나만 제작한다. character_id와 챕터별 character_availability를 분리하고, 이후 이야기 진행에 따른 캐릭터 해금·그 시점에 가능한 인물 선택을 지원하는 방향을 채택했다. 주인공을 강제로 계속 바꾸는 구조는 아니다. 현재 실제 플레이 가능 캐릭터는 garrison_01 한 명이며 후속 인물 자산·능력은 지금 만들지 않는다.

진행 저장은 schema_version과 콘텐츠 ID를 사용하며 배열 순서나 화면 문구를 키로 쓰지 않는다. 설정·챕터 클리어·기록은 업데이트로 이어지고, 신규 챕터의 기본값을 추가해도 기존 진행이 지워지지 않는 마이그레이션 테스트를 둔다. 진행 중인 런은 chapter_id와 content_revision을 고정한다. 호환되지 않는 업데이트에서는 기존 체크포인트를 보존하고 재개 가능 여부를 분명하게 알린다. 후속 챕터의 장비·인물·최종 결말 콘텐츠를 지금 미리 만들거나 1탄에 노출하지 않는다.

## 8. 모듈 경계

모듈은 다음 입력·출력 경계를 따른다. 구체적인 공개 API는 [계약](contracts.md)에 정리한다.

| 모듈 영역 | 파일 영역 예시 | 입력·출력 계약 | 통합 조건 |
|---|---|---|---|
| 전투·성장 코어 | game/core, game/combat, game/progression, 해당 단위 테스트 | 이동 벡터·틱 입력 → 상태 스냅샷·피해/경험치/레벨업 이벤트 | RNG·시간·체력·성장 선택을 렌더링 없이 검증한다. |
| 보스·적·챕터·밸런스 | game/director, game/bosses, chapters/chapter_01, data/enemies | 공통 엔티티·공격 규격과 시간표 → 패턴·예고·보상·대피 이벤트 | 코어 함수를 복제하지 않고 공통 계약만 사용한다. 스토리 시점과 장비 제한을 지킨다. |
| 자체 래스터·오디오 자산 | assets/art, assets/audio, assets/manifest | 스타일 기준·셀 크기·애니메이션 이름 → PNG/오디오/목록 | UI·게임 로직 파일을 수정하지 않는다. 기존 게임 자산은 금지한다. |
| 화면·도트 표현·반응형 UI | game/presentation, scenes/ui, themes, 해당 UI 테스트 | 읽기 전용 RunState·UI 이벤트 → 화면·선택 action | 전투 수치·저장 형식은 수정하지 않는다. 공통 atlas 규격을 따른다. |
| Android·입력·저장 연결 | platform/android, game/input, game/persistence, export 설정 | 공통 action·snapshot 계약 → 패드/터치/생명주기·APK | 정식 키·계정·권한을 임의로 만들거나 바꾸지 않는다. |
| 독립 검증 | tests/integration, validation 문서 | 같은 후보 소스·APK·자산 목록 → AC별 근거와 결함 | 재현 가능한 회귀 테스트와 결함 근거를 남긴다. |

공통 규격은 엔티티 ID, 시간·좌표 단위, RNG, Input action, RunState 버전, 전투 이벤트, 보스 phase/텔레그래프, 자산 셀·anchor와 애니메이션 이름이다.

검증 순서: 공통 규격 → 코어와 입력 → 전투·보스·UI·자산 결합 → 5분 구간 → 전체 30분 시간표와 최종 위협 → Android 회전·패드·저장·성능 → APK 검증.

| AC-12 | 845년 1탄의 사건·인물·장비 순서를 지키고 이후 챕터를 넣지 않는다. | 공식 근거 대조, 챕터 콘텐츠·이벤트 검토 |
| AC-13 | 후속 챕터 데이터 추가와 저장 버전 변경 시 1탄 진행·설정이 보존된다. | 최소 테스트용 새 챕터 fixture와 마이그레이션 테스트; 후속 실제 콘텐츠는 만들지 않음 |
| AC-14 | 캐릭터 에셋 완성 시 중간 미리보기를 전달한다. | 원본 PNG·게임 표시 배율·준비된 애니메이션의 실제 첨부 기록 |

실행 때는 단위/계약 테스트, Godot headless 로드·시뮬레이션, 화면 캡처·상호작용, Android 빌드/패키지 검사, Android 런타임 검증을 증거가 필요한 순서로 조합한다. 동일 후보의 유효한 검증은 재사용한다.

시간 압축 테스트는 스케줄·누수 검출에 쓰되 실제 시간의 30분 플레이를 대체하지 않는다. 성능 목표는 대상 기기에서 평균 60fps, 부하 시 30fps 이상이며 측정 기기·장면·프레임타임·메모리를 함께 기록한다. 아직 측정하지 않은 목표를 달성했다고 쓰지 않는다. 특정 실기기나 패드가 없으면 해당 조합만 미검증으로 남기고 자동 검증 가능한 범위는 계속한다.

## 10. 전달물과 현재 경계

승인 후 첫 전달 목표는 `게임명-v0.1.0-dev1-android.apk`, 대응하는 비공개 GitHub 소스 ref/SHA, 짧은 조작 안내, 검증 결과 및 알려진 제한이다. Play 게시, AAB, 정식 Release, 서버·계정, 멀티플레이, 광고·결제는 첫 범위 밖이다.

DEV 설치 ID와 향후 정식 설치 ID는 분리하고 DEV 업데이트에서 같은 ID·서명 계보·증가하는 versionCode를 유지한다. 키의 지속 보존 경로는 승인된 보안 경로를 확인한 뒤 확정하며, 비밀키·암호를 문서나 저장소에 넣지 않는다. 첫 APK의 패키징 전 이 항목의 가능 여부를 확인한다.

현재 구현 범위와 남은 아트 검토는 [아트 현황](../art/HANDOFF.md), 빌드·서명 절차는 [로컬 Android 빌드](../build/android-local.md)를 참조한다.
